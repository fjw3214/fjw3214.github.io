## 先让内容独立存在

Markdown 是普通文本。即使没有打开博客页面，也可以直接阅读、修改和搜索。配合 Git，文章的修改过程也能够和代码一样被追踪。

对于以阅读为主的个人博客，这是一个容易理解的起点。

## 一篇文章包含什么

在这个仓库中，文章保存在 `posts/` 目录下。文件顶部的元信息描述标题、日期、分类和摘要，正文使用 Markdown 编写。

```yaml
---
title: 我的第一篇文章
date: '2026-10-29'
category: 随笔
tags: [记录]
description: 用一句话描述这篇文章的主要内容。
---
```

正文从元信息结束之后开始。二级、三级标题会成为阅读页的目录，方便快速找到感兴趣的段落。

## 把重复工作交给构建

构建过程读取文章，生成首页、文章列表、分类和独立阅读页。同时输出搜索索引、RSS 和站点地图，避免每次更新都手动修改多处。

```bash
npm install
npm run build
npm start
```

构建结果位于 `dist/`，可以放到支持静态文件的托管服务上。预览服务只用于本地检查。

## 复杂度可以以后再加

评论、在线编辑和账号系统都有各自的维护成本。先把阅读体验、内容组织和更新流程做好，再根据实际需要决定是否增加功能。

如果主要目标是写作，一个容易打开、容易维护、能够持续更新的网站，就已经有了好的开始。
